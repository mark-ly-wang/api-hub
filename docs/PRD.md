## Executive Summary

API Hub 是一个专为Coze工作流创作者打造的API聚合平台,通过双层商业模式解决"便捷使用API"和"创作者变现"两大核心需求。

**核心价值主张:**
- **基础层(所有用户):** 统一API Key管理、灵活的三种计费模式(按次/会员/按量)、智能Coze插件代码生成,让创作者告别多平台账户混乱
- **进阶层(Pro用户):** 白标店铺系统,让创作者贴牌运营自己的API商店,从"批发-零售"差价中获得持续被动收入

**1年目标:** 月利润¥2-5万,成为Coze生态的"标配"API平台,20-50个白标店铺运营,2000-5000名注册用户。

### What Makes This Special

**五大独特优势:**

1. **精准生态定位** - 深耕Coze平台,提供专门优化的插件代码,在垂直领域建立品牌认知
2. **计费系统灵活性** - 三种计费模式(按次/按量/会员)+ 双层会员权益配置,适配不同API特性,灵活性是核心价值
3. **B2B2C变现生态** - 白标店铺让头部创作者成为分销商,形成网络效应和规模化增长
4. **创始人流量优势** - 10万+播放量抖音账号精准触达目标用户,零获客成本冷启动
5. **AI智能辅助** - Admin工具智能生成数据转换代码,降低API配置门槛;未来对话式插件代码生成进一步降低技术门槛

**核心差异化:** 不是通用API聚合平台,而是为Coze创作者量身定制的"API + 变现"双赋能平台。

## Project Classification

**Technical Type:** API Gateway + SaaS B2B2C Platform
**Domain:** API Aggregation / Creator Economy / Fintech (Billing)
**Complexity:** Medium-High

**技术类型解析:**
- **API Gateway:** 统一API代理、请求转发、计费扣费、限流熔断
- **SaaS B2B:** Admin后台管理API、用户、计费配置
- **B2B2C:** 白标店铺多租户架构,创作者运营子平台

**领域特征:**
- **API聚合:** 需要对接多个第三方API供应商,处理不同认证方式和数据格式
- **创作者经济:** B2B2C分销模式,赋能创作者变现
- **金融科技(计费):** 复杂的多模式计费系统、会员权益管理、财务结算

**复杂度来源:**
- 三种计费模式的灵活组合和嵌套参数识别
- 双层会员权益配置(套餐层 + API层)
- 白标店铺的多租户架构和独立计费
- AI数据处理的智能代码生成
- 实时成本控制和风控机制

## Product Scope

### MVP - Minimum Viable Product (Phase 1: 核心便捷性)

**目标:** 让Coze创作者10分钟内从注册到成功调用API,体验"太方便了"的惊喜

**核心能力(不可简化):**

**1. 统一账户与API Key管理**
- 一个账号管理所有API访问
- 一个API Key调用平台所有API
- 余额统一管理和充值
- 消费明细清晰可查

**2. 三种灵活计费模式**
- 按次计费(天气、短信API)
- 按量计费(GPT API,支持嵌套参数识别如`response.usage.tokens`)
- 会员套餐(双层配置:套餐层全局折扣+返现,API层单独权益设置)

**3. API网关核心**
- 请求代理和转发到上游API
- 6步验证流程(Key解析→验证→权限→余额→放行)
- 实时计费扣费
- 速率限制和配额管理
- 错误处理和友好提示

**4. Coze插件代码生成(核心差异化)**
- 每个API自动生成标准Coze插件代码
- 参数自动映射配置
- 一键复制代码到Coze工作流
- 降低技术门槛,开箱即用

**5. Admin后台管理**
- 第三方API接入配置(URL、认证、计费模式、定价)
- AI数据处理:智能生成数据转换代码,简化复杂返回
- 会员套餐管理(价格、期限、折扣、返现)
- API定价管理和会员权益配置
- 用户管理、API调用统计、收入成本分析

**6. 用户前端界面**
- API浏览和详细文档展示
- Coze插件代码展示和复制
- 账户充值(微信/支付宝)
- 消费记录和余额查询
- 会员套餐购买和管理

**MVP排除项(Phase 2):**
- ❌ 白标店铺系统
- ❌ 对话式插件代码生成(MVP仅提供标准模板)
- ❌ 推荐返利系统
- ❌ 优惠券和营销活动

### Growth Features (Post-MVP - Phase 2: 变现生态)

**时间线:** MVP上线后2-3个月

**白标店铺系统(核心增长引擎):**
- 创作者可贴牌运营独立API商店
- 品牌定制(Logo、域名、主题色)
- 独立域名和SSL证书支持
- 批发-零售差价模式
- 终端用户在白标店铺注册获取API Key
- 财务结算系统(创作者收入提现)
- 创作者后台(订单管理、收入统计)

**对话式插件代码生成(降低门槛):**
- 用户描述需求:"我需要一个查天气的插件"
- AI智能理解并配置参数
- 自动生成完整可用的Coze插件代码
- 进一步降低技术门槛

**营销增长工具:**
- 推荐返利系统
- 优惠券和活动管理
- 粉丝专属福利配置

### Vision (Future - Phase 3: 生态扩展)

**时间线:** 1年后

**多平台支持:**
- 从Coze扩展到Dify、FastGPT等AI工作流平台

## API Gateway + SaaS Specific Requirements

作为API Gateway + SaaS B2B2C混合项目,系统需要同时处理:
1. **API网关职责:** 请求代理、计费、限流、监控
2. **SaaS平台职责:** 用户管理、配置管理、数据分析
3. **B2B2C架构:** 为Phase 2白标店铺预留多租户能力

### API Specification

**核心API端点设计:**

**用户端API (面向Coze创作者):**

**认证与账户:**
- `POST /api/v1/auth/register` - 用户注册
- `POST /api/v1/auth/login` - 用户登录
- `POST /api/v1/auth/logout` - 退出登录
- `POST /api/v1/auth/reset-password` - 密码重置
- `GET /api/v1/user/profile` - 获取用户资料
- `PUT /api/v1/user/profile` - 更新用户资料

**API Key管理:**
- `POST /api/v1/keys/generate` - 生成新API Key
- `GET /api/v1/keys` - 查询用户的API Keys列表
- `DELETE /api/v1/keys/:keyId` - 删除/撤销API Key
- `PUT /api/v1/keys/:keyId/rotate` - 轮换API Key

**账户与充值:**
- `GET /api/v1/account/balance` - 查询账户余额
- `POST /api/v1/account/recharge` - 创建充值订单
- `GET /api/v1/account/transactions` - 查询交易记录
- `GET /api/v1/account/usage` - 查询API使用统计

**会员管理:**
- `GET /api/v1/memberships` - 查询会员套餐列表
- `POST /api/v1/memberships/subscribe` - 购买会员套餐
- `GET /api/v1/memberships/my` - 查询我的会员状态
- `POST /api/v1/memberships/renew` - 续费会员

**API浏览与文档:**
- `GET /api/v1/apis` - 浏览API目录(支持分类筛选)
- `GET /api/v1/apis/:apiId` - 获取API详细信息
- `GET /api/v1/apis/:apiId/doc` - 获取API文档
- `GET /api/v1/apis/:apiId/coze-code` - 获取Coze插件代码

**API网关 (统一代理端点):**
- `ANY /gateway/:apiId/*` - 统一API调用入口
  - 请求头需携带 `X-API-Key: {user_api_key}`
  - 路径参数 `apiId` 标识调用哪个API
  - 剩余路径和请求体透传给上游API
  - 响应前计费并扣费

**Admin API (后台管理):**

**API接入管理:**
- `POST /api/v1/admin/apis` - 创建新API配置
- `PUT /api/v1/admin/apis/:apiId` - 更新API配置
- `DELETE /api/v1/admin/apis/:apiId` - 删除API
- `POST /api/v1/admin/apis/:apiId/pricing` - 配置API定价
- `POST /api/v1/admin/apis/:apiId/membership-benefits` - 配置会员权益

**会员套餐管理:**
- `POST /api/v1/admin/memberships` - 创建会员套餐
- `PUT /api/v1/admin/memberships/:id` - 更新套餐配置
- `DELETE /api/v1/admin/memberships/:id` - 删除套餐

**数据统计:**
- `GET /api/v1/admin/stats/users` - 用户统计
- `GET /api/v1/admin/stats/apis` - API调用统计
- `GET /api/v1/admin/stats/revenue` - 收入统计
- `GET /api/v1/admin/stats/costs` - 成本统计

**用户管理:**
- `GET /api/v1/admin/users` - 查询用户列表
- `GET /api/v1/admin/users/:userId` - 查询用户详情
- `PUT /api/v1/admin/users/:userId/status` - 启用/禁用用户

### Authentication & Authorization

**用户端认证:**

**注册/登录方式:**
- 手机号 + 验证码
- 邮箱 + 密码
- 微信/支付宝第三方登录(可选,Phase 2)

**Session管理:**
- JWT Token机制
- Access Token (有效期24小时)
- Refresh Token (有效期30天)
- 支持多设备同时登录

**API Key认证(核心):**
- 用户生成个人API Key
- 格式: `apihub_live_{32位随机字符串}`
- 调用网关API时携带在 `X-API-Key` header
- 后台验证流程:
  1. 解析Key,提取用户ID
  2. 验证Key有效性(未过期/未撤销)
  3. 检查用户权限(账户状态正常)
  4. 检查账户余额(足够支付本次调用)
  5. 检查速率限制(未超配额)
  6. 放行请求

**权限模型:**
- **普通用户:** 调用API、管理自己的Keys和账户
- **会员用户:** 额外享受折扣和特殊权益
- **管理员:** 全平台管理权限(API配置、用户管理、统计查询)
- **超级管理员:** 系统配置、敏感操作

### Multi-Tenancy Architecture (Phase 2 预留)

**当前MVP:** 单租户架构,所有用户共享同一平台

**Phase 2 白标店铺架构预留:**

**租户模型:**
- **平台租户(Platform Tenant):** API Hub官方平台
- **创作者租户(Creator Tenant):** 每个白标店铺是一个独立租户
- 每个租户有独立:
  - 品牌配置(Logo、域名、主题)
  - 用户体系(终端用户在白标店铺注册)
  - 定价策略(批发价基础上自定义零售价)
  - 财务账户(独立收入和提现)

**数据隔离:**
- 物理隔离: 每个租户独立数据库(可选)
- 逻辑隔离: 共享数据库,通过tenant_id字段区分(推荐)
- API调用隔离: 每个租户的终端用户API Key关联到tenant_id

**计费结算:**
- 平台批发价 → 创作者零售价
- 差价归创作者所有
- 平台抽取创作者收入的10-20%作为平台服务费
- 创作者可提现到个人账户

### Permissions & Roles

**角色定义:**

**用户端角色:**
- **普通用户 (Free User)**
  - 注册、登录、充值
  - 生成API Key
  - 调用API(按原价计费)
  - 查看消费记录

- **会员用户 (Member User)**
  - 继承普通用户所有权限
  - 享受全局折扣(如9折/8折)
  - 获得充值返现
  - 特定API会员免费/特殊折扣
  - 优先客服支持

**管理端角色:**
- **API配置员 (API Manager)**
  - 接入新API
  - 配置API参数和定价
  - 生成Coze插件代码模板
  - 无用户数据访问权限

- **财务管理员 (Finance Manager)**
  - 查看收入/成本统计
  - 管理会员套餐
  - 审核充值和提现
  - 无API配置权限

- **客服管理员 (Support Manager)**
  - 查看用户信息
  - 处理用户问题
  - 调整用户余额(需审批)
  - 无系统配置权限

- **超级管理员 (Super Admin)**
  - 所有权限
  - 系统配置
  - 角色分配
  - 敏感操作审计

## User Experience Principles

**核心设计理念: "10分钟从注册到成功调用API"**

产品的UX应该让Coze创作者感觉"太方便了",对比多平台注册管理的混乱体验产生明显的便捷感。

**视觉个性:**
- **简洁专业:** 不花哨,信息密度适中
- **技术感:** 体现API平台的专业性
- **亲和力:** 不冰冷,面向创作者而非纯技术人员
- **品牌色:** 科技蓝/绿色调,传递"效率"和"创新"

**交互原则:**

**1. 零学习曲线**
- 首次使用无需教程,界面自解释
- 关键操作有清晰的引导和提示
- 专业术语配有通俗解释(如"API Key是什么?")

**2. 即时反馈**
- 操作后立即显示结果(充值成功、余额变动)
- 错误提示友好且可操作(而非技术错误码)
- 加载状态明确,不让用户等待焦虑

**3. 透明可控**
- 消费清晰可查,每次API调用扣费可见
- 余额不足提前预警
- 用户随时可控制(撤销Key、停用API)

**4. Coze优先**
- Coze插件代码一键复制是核心体验
- 强调"专为Coze优化"
- 示例和文档以Coze场景为主

### Key Interactions

**关键用户流程:**

**新用户首次体验(10分钟完成):**
1. **注册(1分钟):** 手机号验证码,无复杂表单
2. **充值(2分钟):** 微信/支付宝扫码,最低¥10起充
3. **选API(2分钟):** 浏览API目录,查看文档和价格
4. **生成Key(1分钟):** 一键生成个人API Key
5. **复制代码(1分钟):** 复制Coze插件代码
6. **粘贴测试(2分钟):** 粘贴到Coze工作流,立即测试成功
7. **查看扣费(1分钟):** 返回平台查看消费记录,余额变化清晰

**日常使用流程:**
- **场景:** 需要调用新API
- **流程:** 登录 → 选API → 复制Coze代码 → 粘贴 → 完成 (< 3分钟)
- **体验:** 比注册新平台快10倍

**充值和会员流程:**
- **场景:** 余额不足或想享受折扣
- **流程:** 查看余额提醒 → 充值/购买会员 → 支付 → 即刻生效
- **体验:** 无等待,无审核,即充即用

**Admin核心交互:**
- **添加新API:** 表单引导式录入,AI辅助生成数据转换代码
- **配置定价:** 拖拽滑块设置折扣,实时预览最终价格
- **查看统计:** 可视化图表,关键指标一目了然

**移动端体验(可选Phase 2):**
- 响应式设计,手机端可查余额、充值
- 核心操作保留PC端(复制代码到Coze)

## Functional Requirements

以下功能需求定义了API Hub必须提供的所有能力。每个FR描述"WHAT"(什么能力),而非"HOW"(如何实现)。

### 用户账户与认证 (FR1-FR8)

**FR1:** 用户可以通过手机号+验证码注册账户
**FR2:** 用户可以通过邮箱+密码注册账户

## Non-Functional Requirements

### Performance

**NFR-P1: API网关响应时间**
- 网关转发API请求的额外延迟 < 100ms (P95)
- 目标:用户感觉不到中间层的存在

**NFR-P2: 计费系统性能**
- 单次计费计算耗时 < 50ms
- 嵌套参数解析耗时 < 30ms
- 保证计费不成为请求瓶颈

**NFR-P3: 页面加载性能**
- 用户前端首屏加载 < 2秒
- API文档页面加载 < 1秒
- Admin后台统计图表渲染 < 3秒

**NFR-P4: 数据库查询性能**
- 用户余额查询 < 100ms
- 交易记录查询(100条) < 500ms
- 统计数据聚合查询 < 2秒

**NFR-P5: 并发处理能力**
- 支持1000并发API调用
- 支持100并发充值请求
- 目标:MVP阶段足够,Phase 2横向扩展

### Security

**NFR-S1: 数据传输安全**
- 所有API通信强制HTTPS加密
- TLS 1.2或更高版本
- 禁止明文传输敏感数据

**NFR-S2: 数据存储安全**
- API Key使用AES-256加密存储
- 用户密码使用bcrypt哈希(cost因子≥10)
- 敏感日志脱敏(隐藏API Key、手机号等)

**NFR-S3: 认证安全**
- JWT Token有效期限制(Access Token 24h, Refresh Token 30d)
- 支持Token撤销机制
- 登录失败5次后账户锁定15分钟

**NFR-S4: API Key安全**
- API Key长度≥32字符,使用密码学安全随机数生成
- 支持Key轮换
- Key泄露后可立即撤销

**NFR-S5: 支付安全**
- 集成官方支付SDK(微信/支付宝)
- 支付回调验证签名
- 支付金额二次校验
- 防止重复支付和金额篡改

**NFR-S6: 审计与合规**
- 记录所有敏感操作审计日志(90天保留)
- 日志包含:操作人、时间、IP、操作内容、结果
- 支持审计日志导出

### Scalability

**NFR-SC1: 用户规模**
- MVP Phase 1 支持5,000注册用户
- 支持1,000日活跃用户
- Phase 2 预留扩展到50,000用户的架构能力

**NFR-SC2: API调用量**
- MVP Phase 1 支持200万次/月API调用
- 峰值QPS支持1000
- 通过横向扩展网关节点支持更高QPS

**NFR-SC3: 数据存储**
- 数据库支持1亿条API调用日志记录
- 使用分区表或时序数据库优化查询
- 历史数据归档策略(3个月热数据,1年冷数据)

**NFR-SC4: 多租户扩展(Phase 2预留)**
- 数据模型支持tenant_id逻辑隔离
- 配置表支持租户级别定制
- API调用支持租户级别隔离和限流

### Reliability

**NFR-R1: 系统可用性**
- API网关可用性 ≥ 99.5% (月停机 < 3.6小时)
- 计划内维护提前通知用户
- 故障恢复时间目标(RTO) < 1小时

**NFR-R2: 数据可靠性**
- 计费数据零丢失(事务保证)
- 用户余额数据实时备份
- 数据库每日自动备份,保留7天

**NFR-R3: 第三方API容错**
- 上游API超时时间设置(5秒)
- 上游API失败重试机制(最多3次)
- 上游API不可用时返回友好错误而非系统崩溃

**NFR-R4: 降级策略**
- 非核心功能(如统计图表)故障时不影响核心功能
- 支付网关故障时保留订单,稍后重试
- Admin后台故障不影响用户端使用

### Usability

**NFR-U1: 易用性目标**
- 新用户10分钟内完成注册到首次API调用
- Coze插件代码复制成功率 > 90%
- 用户操作无需查看帮助文档

**NFR-U2: 错误提示**
- 所有错误提示清晰友好,避免技术术语
- 提供可操作的解决方案("余额不足,立即充值")
- 表单验证实时反馈

**NFR-U3: 响应式设计**
- 支持主流浏览器(Chrome, Firefox, Safari, Edge)
- 支持移动端浏览(响应式布局)
- 核心功能在移动端可用(查余额、充值)

**NFR-U4: 国际化预留**
- MVP支持简体中文
- 代码结构支持未来多语言扩展
- 货币显示统一为人民币符号¥

### Integration

**NFR-I1: 第三方API集成**
- 支持REST API标准(JSON格式)
- 支持主流认证方式(API Key, OAuth 2.0, Basic Auth)
- 适配不同API的响应格式

**NFR-I2: 支付集成**
- 集成微信支付官方SDK
- 集成支付宝官方SDK
- 支付回调处理幂等性

**NFR-I3: 短信服务集成**
- 集成阿里云/腾讯云短信服务
- 验证码发送成功率 > 95%
- 发送频率限制(同号码1分钟1次,1小时5次)

**NFR-I4: AI服务集成**
- 集成AI服务(如GPT/Claude)用于数据处理代码生成
- API调用失败时降级到预设模板
- 成本控制(单次生成Token限制)

### Monitoring & Observability

**NFR-M1: 日志记录**
- 所有API请求记录访问日志
- 错误日志包含堆栈信息
- 日志结构化,便于查询分析

**NFR-M2: 性能监控**
- 监控API响应时间(P50, P95, P99)
- 监控数据库查询耗时
- 监控服务器CPU、内存、磁盘使用率

**NFR-M3: 业务监控**
- 实时监控API调用量
- 实时监控收入和成本
- 监控用户注册和活跃趋势

**NFR-M4: 告警机制**
- 系统异常告警(服务宕机、数据库连接失败)
- 业务异常告警(成本超预期、调用失败率高)
- 告警多渠道通知(邮件、短信、企业微信)

### Compliance & Legal

**NFR-C1: 数据隐私**
- 遵守《个人信息保护法》
- 用户可查询和导出个人数据
- 用户可申请删除账户和数据

**NFR-C2: 服务条款**
- 明确服务使用条款和隐私政策
- 用户注册时同意条款
- 条款变更时通知用户

**NFR-C3: API转售合规**
- 确认第三方API供应商允许转售
- 保留供应商合同和授权文档
- 避免侵犯API提供商权益
