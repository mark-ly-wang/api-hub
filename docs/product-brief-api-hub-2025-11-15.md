# Product Brief: api-hub

**Date:** 2025-11-15
**Author:** BMad
**Context:** 创业项目 - Coze生态深耕

---

## Executive Summary

API Hub 是一个专为Coze工作流创作者打造的API聚合平台,通过双层商业模式同时解决"便捷使用"和"收入变现"两大核心需求。

**基础层(所有用户):** 提供统一API密钥管理、灵活的多模式计费系统(按次/会员/按量)、以及智能的Coze插件代码生成,让创作者无需在多个平台注册即可获取所需API能力。

**进阶层(Pro用户):** 提供白标店铺功能,让创作者贴牌运营自己的API商店,从平台"批发"API并以零售价出售,建立可持续的被动收入。

**核心优势:** 创始人作为Coze创作者深度理解用户需求,同时拥有10万+播放量的抖音流量池,实现零获客成本冷启动。

**目标:** 1年内达到月利润¥2-5万,成为Coze生态的"标配"API平台。

## Core Vision

### Problem Statement

Coze工作流创作者面临三层核心痛点：

**发现难题：** 创作者不知道哪里能找到适合Coze工作流的、好用的API。市场上API资源分散,缺乏针对Coze生态的推荐和筛选机制。

**技术门槛：** 直接对接第三方API需要理解不同平台的认证方式、参数格式、数据结构,对非技术背景的创作者来说是巨大障碍。

**账户混乱：** 需要在多个API平台注册账号、管理多个API Key、处理不同的计费规则,账户管理复杂且容易出错。

**变现瓶颈：** 创作者投入大量时间开发优质工作流,但只能依靠工作流本身变现(教学、付费分享),无法从提供API服务中获得持续收入。

### Problem Impact

**时间成本：**
- 在5-10个API平台注册和管理账户
- 每次使用需要切换不同平台查询余额、续费
- 学习每个API的文档和参数配置

**技术成本：**
- 需要理解REST API、JSON格式、认证方式
- 处理数据转换和错误处理
- 调试参数配置问题

**发现成本：**
- 不知道哪些API存在、哪些适合自己的需求
- 试错成本高,购买后才发现不符合预期

**收入损失：**
- 无法将API能力转化为收入来源
- 头部创作者有流量但缺乏变现渠道
- 错过创作者经济的增长红利

### Why Existing Solutions Fall Short

**直接使用第三方API平台：**
- ❌ 需要多个账号和API Key管理
- ❌ 每个平台计费规则不同,成本难以控制
- ❌ 没有针对Coze的集成指导
- ❌ 无变现能力

**RapidAPI等API聚合平台：**
- ❌ 不针对Coze生态,没有专门优化
- ❌ 无智能Coze插件代码生成
- ❌ 无白标能力,创作者无法建立自己的品牌
- ❌ 英文为主,国内创作者门槛高

**自建API：**
- ❌ 开发和维护成本极高
- ❌ 需要专业技术团队
- ❌ 无法覆盖多样化的API需求

### Proposed Solution

API Hub 通过**统一平台 + 灵活计费 + 智能辅助 + 变现生态**四位一体解决方案,重新定义Coze创作者的API使用体验。

**核心解决方案：**

**1. 统一API密钥管理**
- 一个API Key访问所有聚合的API
- 统一账户、统一充值、统一管理
- 告别多平台账户混乱

**2. 灵活的多模式计费系统**
- **按次计费：** 适合天气、短信等按调用次数收费的API
- **按量计费：** 适合GPT等按token消耗收费的API,支持嵌套参数智能识别(如`response.usage.tokens`)
- **会员套餐：** 双层权益配置
  - 套餐层：全局折扣 + 充值返现
  - API层：单独配置排除/特殊折扣/免费
- 三种模式灵活组合,适配不同API特性

**3. Coze插件代码智能生成**
- 提供标准的Coze插件代码模板
- 自动配置参数映射
- 降低技术门槛,开箱即用

**4. AI数据处理能力(Admin工具)**
- Admin配置第三方API时,AI智能生成数据转换代码
- 简化复杂API返回结构
- 统一数据格式,提升用户体验
- 添加平台增值参数(余额提醒、联系方式等)

**5. 白标店铺系统(Phase 2)**
- 创作者可贴牌运营自己的API商店
- 从平台"批发"API,自定义零售价
- 终端用户在白标店铺注册获取API Key
- B2B2C模式赋能创作者变现

### Key Differentiators

**1. 精准定位Coze生态**
- 深度理解Coze工作流创作者需求
- 提供专门优化的Coze插件代码
- 建立在Coze社区的品牌认知

**2. 智能辅助降低门槛**
- 自动生成Coze插件代码(未来对话式生成)
- AI数据处理简化API配置
- 让非技术创作者也能轻松使用API

**3. 灵活计费系统**
- 三种计费模式适配不同API特性
- 双层会员权益配置满足个性化需求
- 灵活性是核心价值,不简化MVP

**4. B2B2C变现生态**
- 白标店铺让创作者成为API分销商
- 头部创作者获得持续被动收入
- 形成网络效应和规模化增长

**5. 创始人流量优势**
- 10万+播放量的抖音账号教授Coze工作流
- 精准触达目标用户群体
- 零获客成本冷启动
- 创始人作为Coze创作者,深度理解用户痛点

## MVP Scope

### Core Features

**MVP Phase 1核心功能(不可简化):**

**1. 用户系统与账户管理**
- 用户注册/登录(手机号/邮箱)
- 统一API Key生成和管理
- 账户余额管理和充值
- 使用记录和消费明细查询

**2. API网关核心能力**
- 请求代理和转发
- API Key验证(6步流程)：
  - 请求到达 → 解析Key → 验证有效性 → 检查权限 → 检查余额 → 放行
- 请求计费和扣费
- 速率限制和配额管理
- 错误处理和响应

**3. 三种计费模式(必须全部实现)**

**按次计费：**
- 每次调用固定价格
- 适用场景：天气API、短信API等

**按量计费：**
- 嵌套参数智能识别(支持2-3层深度)
- 参数路径配置(如 `response.usage.tokens`)
- 系数计算(tokens × 单价)
- 适用场景：GPT API、图像处理等

**会员套餐计费(双层配置)：**

*套餐层配置：*
- 套餐价格和有效期
- 全局折扣率(如 9折、8折)
- 充值返现金额(平台通用货币)
- 多套餐支持(月费/年费/VIP等)

*API层配置(每个API单独设置)：*
- 应用全局折扣(默认)
- 排除会员折扣(会员仍按原价)
- 特殊会员折扣(覆盖全局折扣)
- 会员免费使用

会员过期处理：失去折扣权益,余额保留可继续使用

**4. Admin后台管理**

**第三方API接入配置：**
- API基本信息(名称、描述、分类)
- 上游API配置(URL、认证方式)
- 计费模式选择(按次/按量)
- 定价配置(原价、会员价)
- AI数据处理配置：
  - 智能生成数据转换代码
  - 简化复杂返回结构
  - 添加平台增值参数

**会员套餐管理：**
- 创建/编辑套餐
- 设置价格、有效期、全局折扣、返现金额

**API定价管理：**
- 批量调价
- 会员权益配置(API级别)

**统计和监控：**
- 用户统计
- API调用统计
- 收入和成本分析
- 告警配置

**5. 用户前端**

**API浏览和文档：**
- API目录和分类
- 详细API文档(参数、返回值、示例)
- **Coze插件代码展示**(核心差异化功能)
  - 自动生成的标准Coze插件代码
  - 一键复制到Coze工作流

**账户和充值：**
- 余额显示和充值入口
- 支付集成(微信/支付宝)
- 消费记录查询

**使用统计：**
- API调用次数和消耗统计
- 按时间维度查询
- 余额预警提醒

**会员中心：**
- 会员套餐购买
- 会员权益展示
- 续费管理

### Out of Scope for MVP

**Phase 1 不包含的功能(Phase 2-3):**

**白标店铺系统(Phase 2):**
- 多租户架构

- 工作流市场和模板分享

**高级功能(Phase 3):**

## Financial Considerations

  - 可选：外包部分开发 vs 自主开发

- 按次计费API：单次 ¥0.01 - ¥0.5

**收入来源2 - 会员订阅：**
- 月度会员：¥29 - ¥99/月
- 年度会员：¥299 - ¥999/年

**收入来源3 - 白标店铺(Phase 2)：**

- 或交易分成：白标店铺利润的10-20%

**财务预测(1年目标)：**
- 月收入：¥80,000 - ¥200,000
- 月成本：¥30,000 - ¥80,000(API成本 + 运营成本)
- 月利润：¥20,000 - ¥50,000
- 投资回收期：6-12个月

**现金流管理：**
- 预充值模式,现金流健康
- 用户充值后使用,无账期风险
- 需要预留应急资金应对API成本波动

## Technical Preferences

**技术栈倾向(待技术方案确定):**

**后端技术：**

## Risks and Assumptions

**关键风险与缓解策略：**

**1. API成本控制风险 ⚠️⚠️**
- **风险：** 上游API价格波动或用户滥用导致成本失控
- **缓解措施：**
  - 设置用户配额和速率限制
  - 实时成本监控和告警
  - 多供应商备选,分散风险
  - 预充值模式,避免欠费

**2. 技术复杂度风险 ⚠️⚠️**
- **风险：** 嵌套参数识别、会员双层配置等技术实现复杂
- **缓解措施：**
  - 充分的技术方案设计和评审
  - 分模块开发和测试
  - 寻求技术顾问或外包支持
  - 预留足够开发时间(3-4个月)

**3. 平台依赖风险 ⚠️⚠️**
- **风险：** Coze平台政策变化或生态衰退
- **缓解措施：**
  - 规划多平台扩展(Dify、FastGPT)
  - 建立独立品牌,不完全依附Coze
  - 关注平台动态,及时调整策略

**4. 获客风险 ⚠️ (已大幅降低)**
- **风险：** 无法触达足够目标用户
- **已有优势：**
  - 创始人10万+播放量抖音账号
  - 精准触达Coze创作者
  - 零获客成本冷启动
- **进一步措施：**
  - 内容营销漏斗(教程植入)
  - 粉丝专属福利引流
  - 社群运营和口碑传播

**核心假设：**

**假设1 - 市场需求存在 ✅**
- 假设：Coze创作者愿意为API便捷性付费
- 验证方式：头脑风暴已深度分析,用户调研进一步验证

**假设2 - API转售合规 ⚠️**
- 假设：第三方API供应商允许转售
- 验证方式：需要逐一确认供应商合同条款
- 风险缓解：优先选择明确允许转售的供应商

**假设3 - Coze生态持续增长 ✅**
- 假设：字节跳动持续投入Coze平台
- 依据：Coze是字节AI战略的重要组成部分
- 风险缓解：即使Coze增长放缓,也可扩展到其他平台

**假设4 - 技术可行性 ✅**
- 假设：嵌套参数识别、AI代码生成等技术可实现
- 依据：现有技术已足够成熟
- 验证方式：技术方案设计阶段进行POC验证

**假设5 - 白标模式吸引力 ⚠️**
- 假设：头部创作者愿意运营白标店铺
- 验证方式：MVP上线后与头部创作者沟通测试
- 风险缓解：即使白标模式不成功,基础API业务仍可持续
